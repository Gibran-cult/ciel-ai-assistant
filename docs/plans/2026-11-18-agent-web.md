# Agent di Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pengguna bisa mengaktifkan dan mematikan agent, melihat log aktivitas beserta status keutuhannya, mengatur masa simpan log, dan mencabut perangkat dari web. Hapus akun ikut menghapus semua data agent.

**Architecture:** Web (Streamlit) membaca dan menulis Supabase lewat `ChatStore`, seperti fitur lain. Rantai log diperiksa layanan agent di VPS, yang menyimpan hasilnya per tugas, jadi kunci rantai tidak pernah keluar dari VPS (D14). Persetujuan aktivasi dicatat web di `consent_events`, dan layanan menolak login perangkat tanpa persetujuan itu (D15). Tampilannya satu tab "Agent" di dialog Pengaturan (D16). Logika tampilan log ada di modul murni `agent_log.py` supaya bisa diuji tanpa Streamlit.

**Tech Stack:** Python, Streamlit (`AppTest` untuk uji), Supabase/PostgREST, FastAPI (layanan dari 2B), `unittest`.

**Spec:** [`docs/privacy-consent.md`](../privacy-consent.md) bagian 1 (model data), 2 (form agent), 3 (tabel agent), 4 (pilihan di Pengaturan). [`docs/design-system.md`](../design-system.md) bagian "Log aktivitas" dan pesan alasan. [`docs/security.md`](../security.md) bagian 3 (log aksi). [`docs/decisions.md`](../decisions.md) D14, D15, D16. [`docs/roadmap.md`](../roadmap.md) task 2.19 sampai 2.22.

## Cakupan

| Termasuk | Tidak termasuk |
|---|---|
| Tab Agent: aktivasi dan penarikan, log aktivitas, unduh log, perangkat, masa simpan | Tampilan agent di ekstensi dan desktop (Fase 3 dan 5) |
| `consent_events` untuk aktivasi, penarikan, dan masa simpan | `consent_events` untuk cookie, ketentuan, dan pengguna tanpa login (`privacy-consent.md` bagian 1 dan 2, rencana sendiri) |
| Pemeriksaan rantai dan penghapusan log lama di layanan | Mengubah `terms.LEGAL_VERSION`, Privasi, atau daftar subprosesor (langkah pemilik sebelum agent dirilis) |
| Hapus akun ikut menghapus data agent | Pilihan tangkapan layar dan izin aplikasi atau folder (desktop, Fase 5) |

## Global Constraints

- Keputusan pemilik: D14 rantai diperiksa di VPS, `AGENT_CHAIN_KEY` tidak pernah masuk secrets Streamlit. D15 persetujuan di web, layanan menolak login perangkat tanpanya, penarikan mencabut semua perangkat. D16 tab "Agent" di Pengaturan, hanya untuk akun yang login.
- Tab Agent hanya muncul kalau secret Streamlit `AGENT_WEB_ENABLED` bernilai persis `"1"`, akun login, dan `CHAT_STORE` aktif. Tanpa secret itu, app sama persis dengan sekarang.
- Semua perubahan tampilan (Task 5) berhenti tanpa commit sampai pemilik mengecek sendiri di browser dan menulis "commit" (aturan tetap pemilik). Task lain boleh di-commit seperti biasa.
- Teks persetujuan dan teks penjelasan di tab Agent adalah draf, ditandai `[PERLU DICEK]` di komentar kode dan di dokumen. Tanpa kotak centang yang terisi otomatis. Satu tujuan per centang (`privacy-consent.md` bagian 2).
- Masa simpan log: 30 hari bawaan, 90 hari kalau dipilih pengguna. Tidak ada pilihan lain.
- Versi teks persetujuan agent: `AGENT_CONSENT_VERSION = "2026-11-18"` di modul baru `agent_consent.py` (tanpa impor Streamlit, ikut disalin ke image layanan).
- Riwayat `consent_events` tidak ikut terhapus oleh Hapus akun, sama dengan `consents` sekarang.
- Waktu di log ditampilkan dalam Asia/Jakarta, format `HH.MM` untuk hari ini dan `D MMM HH.MM` untuk hari lain.
- SQL baru ditambahkan di akhir `docs/chat_store.sql`: RLS aktif tanpa policy, fungsi di-`revoke` dari `public, anon, authenticated`, bisa dijalankan ulang.
- Agent tidak menulis nilai rahasia. Setiap modul uji baru masuk daftar `ci.yml` pada commit yang sama.
- Komentar kode bahasa Indonesia, nama fungsi dan variabel bahasa Inggris. Pesan commit tanpa baris atribusi alat AI.

## Review Focus

1. **Pengguna menarik persetujuan saat tugas sedang berjalan.** Semua perangkat dicabut, tugas berhenti di aksi berikutnya (`client_gone`), dan login perangkat baru ditolak sampai pengguna mengaktifkan lagi. Uji di Task 2 dan 5.
2. **Log yang dimanipulasi di database.** Baris diubah, dihapus di tengah, atau dihapus di ujung. Tab Agent menampilkan "Log rusak" atau "Ada catatan yang hilang" untuk tugas itu, tidak "Utuh". Uji di Task 2 (pemeriksa) dan Task 3 (label).
3. **Hapus akun saat ada tugas berjalan.** Perangkat, token, tugas, log, dan pengaturan agent hilang dalam satu transaksi, dan tugas berhenti. Uji di Task 1 dan 4.
4. **Akun lain.** Tab Agent hanya membaca dan mengubah baris milik akun yang login, termasuk saat mencabut perangkat dengan ID milik akun lain. Uji di Task 1 dan 5.
5. **Isi log yang aneh.** Jenis aksi yang tidak dikenal, alasan kosong, target panjang, atau teks yang mirip HTML tetap tampil sebagai teks biasa. Uji di Task 3.
